# 本地自动化可用性实测

日期：2026-10-10。对象：安装在 `~/Applications/ClipShelf.app` 的开发构建；通过原生桌面自动化操作 ClipShelf 与文本编辑，不以单元测试代替真实操作。测试仅使用新建文档中的合成英文、中文和代码。

**结论：基础记录、搜索、选卡和复制回填可用；尚不能判定跨 App 一键粘贴可用，也未达到 Paste 的流畅体验。**

## 实测结果

| 场景 | 观察 | 结论 |
| --- | --- | --- |
| 复制英文、中文、代码 | 三项均进入历史，正文正确，新复制内容在前 | 通过 |
| 中文搜索“会议” | 只返回对应中文卡片 | 通过 |
| 不存在的关键词 | 显示 0 条和恢复指引，清除条件后恢复全部条目 | 通过 |
| 键盘选卡 | Return 从搜索进入结果，Right 选中下一张卡片 | 通过 |
| 历史内容复制回文本编辑 | 双击中文卡片，再显式执行 ⌘V，原测试光标位置插入正确中文一次 | 复制降级路径通过；不是自动粘贴通过 |
| 一键粘贴回原 App | 安装构建显示“复制模式 · 授权后可直接粘贴” | 当前构建权限未生效，未通过验收 |
| 连续复制同一项 | 再次复制后历史总数不增加 | 通过 |
| A→B→A 重复复制 | 出现两张相同文字的 A 卡片；源码只比较最近一条记录 | 当前设计限制，影响历史整洁度 |
| 复制过程中选区提示 | 曾出现“选中内容已变化…这条内容在编辑期间发生了变化”；清空搜索后恢复 | 已复现体验问题，具体触发链仍待修复验证 |
| 来源 App | 文本编辑的自动化复制显示为 ChatGPT | 自动化路径下异常；工具后台输入可能影响前台归属，不能直接推断普通用户复制也错误 |
| Esc 隐藏 | 后续工具读取又显示面板；应用 reopen 会重新打开隐藏面板 | 受自动化激活干扰，未作为通过或失败证据 |

## 使用感受与处理顺序

1. 固定本地安装身份和可持续的签名方式，解决重新构建后自动粘贴授权不延续的问题；随后由自动化验证原光标、原焦点和仅插入一次。本次未改系统权限，也未要求用户再次代测。
2. 修复普通复制时突兀的“编辑期间变化”提示，明确重复历史的产品行为。当前实现只合并连续相同采集，不能宣称全历史去重。
3. 收拢主面板中的筛选和管理控件。当前分组、设备、类型、来源、时间等占用多行，找内容这一核心操作不够突出。

本次未测试图片/文件粘贴、多显示器、全屏 Space、重启持久化或同步，不推断这些场景已通过。没有做 Paste 订阅版的同机对照或端到端延迟测量。
