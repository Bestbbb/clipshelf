## 本机签名边界

`python3 scripts/setup-local-signing.py` 在仓库外建立专用钥匙串与开发身份，只允许签名工具访问私钥，不修改证书信任、系统根证书或辅助功能授权。构建脚本仅在该身份被 macOS 判为有效时采用；否则明确提示仍为临时签名预览包。发布模式继续要求 Developer ID 身份，不能用本机证书替代公证发行。

身份固定依赖证书私钥而非放宽为仅检查 Bundle ID；依据 [Apple Code Signing Tasks](https://developer.apple.com/library/archive/documentation/Security/Conceptual/CodeSigningGuide/Procedures/Procedures.html)。首次从旧临时签名迁移仍可能需要系统重新确认辅助功能；不能承诺完全不需要一次授权。

2026-10-10，经用户明确确认，已对专用证书设置当前用户域、仅 `CodeSigning` 用途的信任。前后导出核对：只新增一项，原有信任条目未改动。实测发现仅向 `codesign` 传 `--keychain` 仍报告找不到身份，因此本地构建通过 `with-local-signing.py` 临时加入该钥匙串，构建返回后移除；若其他应用并发修改搜索列表，则保留其变化。4 项脚本回归覆盖失败恢复、启动失败、并发变化及原本已存在的钥匙串。

已安装包及改变 Info.plist 内容的验证副本均通过深层严格签名验证；两者 cdhash 不同，designated requirement 同为 Bundle ID 与专用证书叶指纹绑定。验证副本没有运行。这确认代码签名身份稳定，不等于已证明辅助功能授权跨更新延续或跨 App 粘贴成功。
