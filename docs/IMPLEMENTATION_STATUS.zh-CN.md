# ClipShelf 实现与验证状态

更新：2026-10-09。目标仍为完整对齐 Paste for Mac 的 F01–F19；本文记录当前差距，不改变验收范围。

## 当前可运行入口

原生工程位于 `native/`，`scripts/build-macos.sh` 生成开发用 `build/ClipShelf.app`。当前签名为本机 ad-hoc 签名，尚未公证，不是完整正式发行版。

本地构建命令和演示入口见 [README](../README.md)。开发数据独立保存在 `~/Library/Application Support/ClipShelf Development`。第一次正常运行必须选择开始记录；演示模式仅使用合成内容。

## 已取得的证据

- Apple silicon / macOS 26.4.1 / Xcode 26.5：2026-10-09 22:11 的原生release构建成功，生成的开发bundle通过本机签名校验；包内三项App Intents元数据均为`openAppWhenRun=false`、后台模式。尚未验证Shortcuts宿主实际冷启动行为。
- 2026-10-09 22:11 完整运行150项原生测试：0失败、1项跳过；跳过项为本机不可用的FoundationModels真实模型测试。
- 上述剪贴板测试仅访问随机命名的私有pasteboard，不读取用户系统剪贴板。
- 本机演示UI已检查正常/紧凑布局、六张含PNG合成卡片、搜索、第一次Return进入结果、第二次Return调用选中项、ShiftRight多选、只读预览、编辑取消并保留原文。演示没有执行真实系统粘贴，不能替代F04的跨App验收。
- 真实Vision测试识别了合成图片上的文字并检查归一化区域；不代表全部图片/OCR语言质量达标。
- MCP包含实际本地HTTP与Node进程往返测试；CloudKit测试使用合成数据、模拟传输和无配置拒绝门禁，没有连接真实iCloud。
- 上下文建议以注入的合成上下文测试权限和取消。真实FoundationModels可用性测试在当前机器跳过，不能声称实际模型推理已验收。
- 加密备份已测试随机化、错误密码、盐与密文篡改、失败不改库及附件字节恢复；明文只在本机临时目录暂存，目标目录仅接收密文。
- [历史检索基准](../native/Benchmarks/README.md)保留全部合成夹具原始样本：10k记录核心查询最慢p95为8.265 ms；这不包含输入、渲染和动效，不代表端到端体验已达标。
- 本机Xcode的`IDESimulatorFoundation`与`DVTDownloads`发生符号不匹配，分享扩展工程在项目解析前被工具自身阻断；SwiftPM应用构建和扩展源码检查不能替代完整Xcode构建。真实AppGroup访问需要同组签名。

图片与富文本等剪贴板表示包含原始字节；文件记录目前保存本机文件URL引用。来自系统分享的文件会复制到主应用的私有目录，但备份或另一台Mac收到该引用并不等于同时获得文件字节，文件跨机可用性仍需补齐。
