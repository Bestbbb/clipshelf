# ClipShelf 实现与验证状态

更新：2026-10-09。目标仍为完整对齐 Paste for Mac 的 F01–F19；本文记录当前差距，不改变验收范围。

## 当前可运行入口

原生工程位于 `native/`，`scripts/build-macos.sh` 生成开发用 `build/ClipShelf.app`。当前签名为本机 ad-hoc 签名，尚未公证，不是完整正式发行版。

本地构建命令和演示入口见 [README](../README.md)。开发数据独立保存在 `~/Library/Application Support/ClipShelf Development`。第一次正常运行必须选择开始记录；`--demo` 仅使用合成内容且不写系统剪贴板。新增 `--validation` 使用临时数据库、独立偏好与 OCR 缓存，禁用剪贴板采集和后台集成；它运行正常查询与粘贴流程，用户选中粘贴时仍会写系统剪贴板，不能把它当作不写剪贴板的演示。切换模式前先退出已有实例。

## 正在关闭的差距

本轮已复核两行筛选布局、多板组合、板内单项键盘/鼠标排序与OCR预览。显式多板勾选在输入搜索词后保留；从单板浏览开始文字搜索时回到全局。排序只提交移动条目与插入锚点，不以当前分页替换整板；后台版本不匹配时拒绝并重新查询。多选/分页/并发失败恢复仍需实机验收。

手动排序视图中，普通拖动仅在板内调序，按住Option拖出原始内容；普通历史保留直接拖出。此交互有明确界面提示，仍需与Paste实机手势对标。卡片文字/图片的命中统一交由卡片处理；导出异步读取按一次鼠标手势绑定，松开或取消后不能迟发。

真实浏览器目标与辅助功能授权后的直接粘贴仍待验收。本轮尝试通过CUA打开本地`file://`网页夹具被URL安全策略拒绝，没有绕过或改用代理；以原生TextEdit空白临时文稿作为替代验证目标，不能替代浏览器输入框/富文本兼容结论。此前公开GitHub链接预览通过，也不能替代浏览器接收粘贴测试。

先完成核心组件集成和稳定构建，继续补齐系统集成、同步共享与智能建议。同步、MCP和模型功能必须具备独立关闭、授权与失败状态；未配置的云容器、未授予的系统权限均按真实状态展示。

采用 [对标清单](BASELINE_CHECKLIST.zh-CN.md)记录公开资料与有条件时的试用观察。没有Paste订阅不阻止实现；未取得实机证据的细节保持待验证。
