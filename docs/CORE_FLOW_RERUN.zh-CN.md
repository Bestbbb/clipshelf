## 本轮最小改动

1. 增加 `--diagnostic-trace`，可在普通模式输出结构化追踪；保留旧验证模式追踪开关。
2. 记录热键注册 OSStatus、activation/stack 类型与实际回调收到事件。
3. 记录应用生命周期拒绝热键调用的情况。
4. 追踪仅包含固定事件、状态、进程/应用标识和布尔值，不包含剪贴内容、窗口标题、文件路径或任意错误文本。输出到 stderr，运行时保存到本机文件。

12 项相关回归通过，覆盖追踪开关、普通模式保持原数据域、输出字段与热键注册协调；稳定本地签名构建及签名校验通过。最后一次只增加热键类型字段后，再重跑文本编辑主流程验证最终安装构建。

**没有取消 AX 窗口/输入元素保护。** 本轮 Chrome 和 VS Code 均观察到焦点就绪和实际插入，不支持“Electron 接收方一定被 CFEqual 拦截”的断言。关闭面板后的失败提示仍可能不可见，本轮没有触发该失败分支，也没有宣称修复它。

## 测试过程中的失败与修正

- 最初测试脚本用阻塞等待，没有正确等待应用激活与窗口事件处理；复制未得到测试文本，却被脚本当作复制成功。随后增加 run loop 等待，并逐次核对真实系统剪贴板等于合成源文本。
- 一次测试在唤起前发现前台已变为 Codex，未能形成文本编辑验收。后续在唤起前重新准备目标并检查前台；继续输入前也检查目标，避免向其他应用输入。
- VS Code 未聚焦编辑器时 AX 树没有文本区域。测试改为先聚焦该测试窗口的编辑组，最终以保存文件作为内容证据。
- 鼠标测试第一次找不到合成文本编辑窗口；重新打开该测试文件后完成双击验证。

这些是测试准备或环境问题，不作为用户最后一次失败的已确认原因。早期失败日志与后续成功结果分别保留。
