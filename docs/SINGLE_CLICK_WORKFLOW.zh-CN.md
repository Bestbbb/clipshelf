# 单击回填原输入框：本轮修改与验收

后续状态：用户报告 Codex 等输入框仍不能自动回填。此文记录前轮 Cursor 的有限验收；最新通用恢复修复和未验收项见[通用输入位置恢复记录](GENERIC_PASTE_WORKFLOW.zh-CN.md)。

日期：2026-10-10。用户最新确认基础功能可用，当前优先级是功能动线，UI 美化随后处理。目标是：**Cursor 输入框保留原光标 → 打开 ClipShelf → 找到记录 → 单击卡片 → 插入原输入位置并继续工作。**

## 修改

- 普通单击在鼠标于卡片内释放后粘贴，不再要求先选中再双击。
- 鼠标按下时保留选择和拖动准备；拖动、卡片外释放和取消不粘贴。⌘/Shift 单击保留多选。
- 双击的第二次点击不再派发粘贴，无障碍按钮动作也直接粘贴。
- 保留原目标 App、窗口和输入元素检查；更新面板提示、16 种语言的帮助文字与产品/技术文档。

## 验证边界与过程记录

本轮桌面调用通过应用打开/reopen 入口。桌面工具向 Cursor 发送 ⌘⇧V 时执行了其本地粘贴动作，没有观察到 ClipShelf 的全局热键回调；因此不将这次尝试计为热键通过。此前系统事件流热键结果留在[核心流程重跑记录](CORE_FLOW_RERUN.zh-CN.md)。本轮只宣称上述 Cursor 文本动线通过。

中间尝试出现前台应用变化，面板显示音乐和另一个 App 作为接收方，这些尝试未纳入 Cursor 通过结果。普通运行追踪还包含 16:58:37 一次另一个 App 的粘贴完成，无法仅凭当前追踪确定其触发来源；没有将整个日志描述为“只发生两次粘贴”或将这条算作受控测试通过。

当前自动化不等于物理键盘验收、长期日常使用验收或全应用兼容性。富文本、图片、文件接收，以及 Paste 的全量功能与体验对比仍需分别验收。此前失败记录保留，但“完全不可用”已被用户最新的“基础功能可用”反馈更新。
