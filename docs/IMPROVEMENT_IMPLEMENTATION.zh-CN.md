### 对原建议的必要调整

W1.3 的文字先要求调用 `dismiss()`，随后等待双击间隔，却又要求第二下落在仍可见的面板上，这两个动作顺序矛盾。实现采用**先等待，后收起**。否则仅删除透明窗口，会重新暴露原来的点击穿透问题。

这个选择有明确代价：鼠标点击需要等待系统双击间隔的剩余部分，具体时间随用户的 macOS 设置变化。Return 和 Quick Paste 不需要这段等待。尚不能声称操作速度已经达到 Paste。

**2026-10-31 修订：** 用户实际反馈单击粘贴明显卡顿，等待方案改为“立即收起并粘贴，用整块面板区域的非激活透明窗口接住剩余双击间隔”。与旧 `PasteClickShield` 的区别：覆盖整个面板而非 12×12 点，窗口不能成为 key/main，再次打开面板时立即撤下；鼠标仍按住或第二下已被面板接收时，仍按原规则等待释放。实测 TextEdit 点击到插入约 0.46 秒（含测量开销，此前约 1.1 秒）；在多行文档覆盖面板区域的条件下，150/300/450 ms 双击均只插入一次且光标未移动，1.2 s 对照组按预期移动光标。Stage Manager、录屏和辅助工具场景仍未验收。

AX 超时是对象级设置，不能假设给一个应用对象设超时后其他相等对象也继承。实现同时约束每个实际访问的对象，并在一次快照中共享预算。API 语义见 [Apple 的 AXUIElementSetMessagingTimeout 文档](https://developer.apple.com/documentation/applicationservices/1459345-axuielementsetmessagingtimeout)。`cannotComplete` 也可能来自通信失败，因此 `ax_timeout` 是诊断分类，不证明目标一定被挂起。

### 全量测试仍有失败

完整运行：**1,400 项，1 项跳过，20 个失败断言/错误，涉及 18 个失败用例**，见 `full-tests.log`。集中在图片导出、图片旋转的 OCR 缓存、OCR 预览、编辑提交和系统集成，主要错误为 `StorageWriteFailure.coordinationUnavailable`。

另从 Git 导出**未修改的基线**到 `build/improvement-p1/baseline/`，使用独立构建目录复跑这些测试：42 项相关测试和 6 项系统集成测试，复现相同的 18 个失败用例、20 个错误。对照见 `baseline-tests.log`、`baseline-system-tests.log`、`regression-comparison.json`。没有把清空共享缓存作为“通过测试”的手段。

失败发生在未修改的存储协调代码校验注册表与目录身份的位置。现有共享存储预算状态需要单独调查；本轮没有修复这个问题，也没有将全量测试描述为通过。后续工程卫生工作应让测试使用独立的预算/缓存上下文，而不是依赖真实用户缓存。

### 真实跨 App 验收仍未完成

使用独立的 `TextEdit-target.txt` 和隔离验收库，不在用户的真实会话中插入测试文本。

本轮自动化确认了如下限制：

1. 向文本编辑发送组合键未产生 `hotkey_received`。热键已注册，但这条自动化输入不能证明物理热键入口。
2. 工具读取 ClipShelf 状态会触发 `reopen`，不能把它记作热键唤起。
3. 面板坐标双击返回 `noWindowsAvailable`；因此没有真实鼠标交接的接收端证据。
4. 前台在测试间发生切换，目标检查多次发现接收端不是测试文稿；因此跳过了粘贴，没有往其他 App 输入框插入测试数据。

这些尝试不计为“原光标插入一次、继续输入正确”的成功，不替代规格要求的连续十次完整流程。日志和汇总分别为 `validation.jsonl`、`validation-summary.md`。
